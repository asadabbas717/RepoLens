# Contributing

Start with [development setup](docs/development.md) and the
[architecture contract](docs/architecture.md). Implement one roadmap milestone
or coherent feature at a time. Include behavioral tests, rule evidence and
limitations, remediation, and documentation changes with each analyzer.

Run all quality gates before requesting review. Significant design decisions
need an ADR with context, consequences and alternatives. Do not weaken gates
to hide failures, introduce unused dependencies, or execute fixture repositories.
Avoid secrets in examples, fixtures, logs and reports.

The owner has not selected an open-source license yet; resolve licensing before
accepting external contributions or publishing a release.
